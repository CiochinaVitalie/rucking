# AI Token Efficiency Options

Этот файл перечисляет практические варианты, которые помогут снизить расход токенов при работе AI с проектом на `Raspberry Pi Pico`, `A4988` и `Ruckig`.

## 1. Проектный Skill

Создать отдельный skill под этот репозиторий, в котором зафиксировать:

- что проект использует `Raspberry Pi Pico`
- что управление построено вокруг `A4988Stepper`
- что для планирования движения используется `Ruckig`
- где находятся ключевые файлы проекта
- какие инварианты и ограничения нельзя ломать
- как правильно собирать проект

Польза:

- AI не нужно каждый раз заново считывать архитектуру проекта
- меньше повторяющегося контекста в переписке
- меньше токенов уходит на объяснение базовых вещей

## 2. Отдельный Файл Конфигурации Осей

Вынести параметры осей и шаговиков в отдельный файл, например:

- `config/stepper_axes.hpp`
- `config/axes.hpp`

Туда можно поместить:

- шаг двигателя
- микрошаг
- передаточное число
- лимиты движения
- инверсии направления
- тайминги `STEP` и `DIR`
- безопасные пределы скорости и ускорения

Польза:

- AI не нужно читать весь `rucking.cpp`, чтобы понять механику
- все параметры оси находятся в одном месте
- проще вносить изменения без лишнего анализа проекта

## 3. Короткий `docs/PROJECT_CONTEXT.md`

Создать краткий файл с постоянным контекстом проекта.

Что в нём полезно держать:

- цель проекта
- используемую плату
- драйверы и двигатели
- способ перевода градусов в шаги
- важные ограничения физики и электроники
- критерии корректных изменений
- обязательные шаги проверки после правок

Польза:

- вместо чтения многих файлов AI получает компактный источник истины
- снижается объём служебного контекста в диалоге

## 4. Несколько Узких Мини-Skill

Вместо одного большого skill можно сделать несколько маленьких, каждый под свою задачу:

- `pico-build`
- `stepper-tuning`
- `motion-planning`

Примеры назначения:

- `pico-build` описывает только сборку и структуру CMake
- `stepper-tuning` описывает тайминги, лимиты и параметры шаговиков
- `motion-planning` описывает использование `Ruckig`

Польза:

- подгружается только нужный контекст
- меньше токенов тратится на нерелевантную информацию

## 5. Жёсткий Маршрут Работы Для AI

Можно заранее определить правила работы агента с этим проектом:

- сначала читать только `CMakeLists.txt` и связанные `.hpp` или `.cpp`
- не сканировать весь репозиторий без причины
- искать по коду через `rg`
- при изменениях в драйвере шаговика не трогать несвязанные части проекта
- после правок обязательно запускать сборку

Польза:

- уменьшается объём исследования проекта
- снижается число лишних чтений файлов
- уменьшается расход токенов и время на задачу

## 6. Явная Карта Типовых Задач

Можно создать небольшой список типовых задач и ожидаемого маршрута действий.

Примеры:

- изменить параметры шаговика
- поправить CMake
- добавить новую ось
- подстроить ограничения движения
- проверить интеграцию `Ruckig`

Для каждой задачи можно зафиксировать:

- какие файлы читать в первую очередь
- какие файлы обычно не нужно трогать
- какой минимальный набор проверок нужен

Польза:

- AI не строит маршрут заново на каждую похожую задачу
- снижается количество промежуточного анализа

## 7. Отдельный Файл Для Аппаратных Предпосылок

Можно завести файл наподобие:

- `docs/HARDWARE_NOTES.md`
- `docs/STEPPER_ASSUMPTIONS.md`

Что туда вынести:

- модель двигателя
- модель драйвера
- напряжение питания
- выставленный ток
- режим микрошагов
- наличие редуктора
- механические пределы
- известные проблемы стенда

Польза:

- AI не нужно каждый раз спрашивать или выводить это из кода
- легче различать, что взято из даташита, а что из эксперимента

## 8. Стабильные Соглашения По Именам И Структуре

Чем меньше двусмысленностей в проекте, тем меньше токенов уходит на интерпретацию.

Полезные соглашения:

- все конфиги осей лежат в одном месте
- все единицы измерения явно указаны в именах
- все аппаратные лимиты вынесены в конфиг
- файлы названы по роли, а не абстрактно

Примеры:

- `max_velocity_deg_s`
- `dir_setup_time_us`
- `pan_axis_config`

Польза:

- AI тратит меньше контекста на догадки
- уменьшается вероятность лишних уточнений

## Рекомендуемый Минимум Для Этого Проекта

Если делать только самое полезное, то стоит внедрить:

1. `docs/PROJECT_CONTEXT.md`
2. отдельный файл конфигурации осей
3. проектный skill для `Pico + A4988 + Ruckig`

Это даст наилучшее снижение расхода токенов без лишней инфраструктуры.
